# 1. 서론

## 1.1 목적 및 범위

본 문서는 Mini Drive(클라우드 파일 공유 시스템)의 요구사항을 분석하고 시스템의 기능 및 구조를 명확히 정의하기 위한 문서이다.

시스템에서 제공해야 하는 파일 관리, 공유, 검색, 권한 관리, 버전 관리 기능 등을 분석하며 기능적 요구사항과 비기능적 요구사항을 기반으로 시스템 구조를 도출한다.

또한 정적 분석, 동적 분석, CRC 카드 및 요구사항 추적표를 통해 시스템 설계의 기반 자료로 활용한다.

---

## 1.2 용어 정의

| 용어       | 설명                         |
| -------- | -------------------------- |
| 사용자      | 시스템에 로그인하여 파일을 관리하는 일반 사용자 |
| 관리자      | 사용자 및 시스템을 관리하는 사용자        |
| 클라우드 저장소 | 파일을 저장하는 온라인 저장 공간         |
| 공유 링크    | 외부 사용자에게 제공되는 파일 접근 URL    |
| 메타데이터    | 파일명, 업로드 시간, 크기 등의 부가 정보   |
| 버전 관리    | 파일 수정 이력을 저장하고 복원하는 기능     |
| 접근 권한    | 읽기, 수정, 댓글 등의 파일 접근 권한     |

# 2. 시스템 개요

### 2.1.1 Actor Table

| Actor  | Role                             |
| ------ | -------------------------------- |

## 2.2 기능 분류 및 설명

---

### 2.2.1 회원가입을 한다.

Use Case Name : 회원가입을 한다.
ID : U_01
Importance Level : high
Primary Actor : 사용자
Use Case Type : Detail, essential

### Brief Description

사용자가 이메일과 비밀번호를 이용하여 회원가입을 수행한다.

### Stakeholders and Interests

사용자 : 시스템을 사용하기 위해 계정을 생성하고자 한다.

### Trigger

사용자가 회원가입 버튼을 누른다.

### Normal Flow of Events

1. 사용자는 이메일과 비밀번호를 입력한다.
2. 사용자는 회원가입 버튼을 누른다.
3. 시스템은 회원가입 정보를 저장한다.
4. 시스템은 회원가입 성공 메시지를 출력한다.

### Alternate / Exceptional Flows

2.a1 : 입력값이 공란인 경우 실패 메시지를 출력한다.
2.a2 : 중복 이메일인 경우 실패 메시지를 출력한다.

---

### 2.2.2 로그인을 한다.

Use Case Name : 로그인을 한다.
ID : U_02
Importance Level : high
Primary Actor : 사용자
Use Case Type : Detail, essential

### Brief Description

사용자가 이메일과 비밀번호를 이용하여 로그인한다.

### Trigger

사용자가 로그인 버튼을 누른다.

### Normal Flow of Events

1. 사용자는 이메일과 비밀번호를 입력한다.
2. 사용자는 로그인 버튼을 누른다.
3. 시스템은 로그인 정보를 검증한다.
4. 시스템은 메인 화면으로 이동시킨다.

### Alternate / Exceptional Flows

3.a1 : 로그인 실패 시 오류 메시지를 출력한다.

---

### 2.2.3 파일을 업로드한다.

Use Case Name : 파일을 업로드한다.
ID : U_03
Importance Level : high
Primary Actor : 사용자
Use Case Type : Detail, essential

### Brief Description

사용자가 파일을 시스템에 업로드한다.

### Trigger

사용자가 업로드 버튼을 누른다.

### Normal Flow of Events

1. 사용자는 업로드할 파일을 선택한다.
2. 사용자는 업로드 버튼을 누른다.
3. 시스템은 파일 및 메타데이터를 저장한다.
4. 시스템은 업로드 성공 메시지를 출력한다.

### Alternate / Exceptional Flows

2.a1 : 지원하지 않는 파일 형식인 경우 실패 메시지를 출력한다.
2.a2 : 저장 공간이 부족한 경우 실패 메시지를 출력한다.

# 3. 요구사항 명세

## 3.1 정적 분석

### 주요 클래스 구성

| 클래스   | 설명                  |
| ----- | ------------------- |
| 사용자   | 파일 관리 기능을 수행하는 사용자  |
| 관리자   | 사용자 및 시스템을 관리하는 관리자 |
| 파일    | 업로드된 파일 정보를 저장      |
| 폴더    | 파일 분류를 위한 폴더 객체     |
| 파일 DB | 파일 메타데이터 저장소        |
| 공유 정보 | 파일 권한 및 공유 대상 정보    |
| 버전 관리 | 파일 변경 이력 관리         |
| 로그 DB | 접근 기록 및 시스템 로그 저장   |
| 외부 링크 | 외부 공유 URL 관리        |

---

### 클래스 관계 설명

* 사용자는 여러 개의 파일을 소유할 수 있다.
* 파일은 하나 이상의 버전 정보를 가진다.
* 공유 정보는 파일과 사용자 사이의 권한 관계를 저장한다.
* 로그 DB는 사용자 활동 정보를 저장한다.
* 외부 링크는 특정 파일과 연결된다.

## 3.3 동적 분석

### 3.3.1 회원가입을 한다.

1. 사용자는 회원가입 요청을 보낸다.
2. 시스템은 이메일 중복 여부를 확인한다.
3. 시스템은 회원 정보를 저장한다.
4. 시스템은 성공 메시지를 반환한다.

---

### 3.3.2 로그인을 한다.

1. 사용자는 로그인 요청을 보낸다.
2. 시스템은 사용자 정보를 검증한다.
3. 로그인 성공 시 메인 화면으로 이동한다.
4. 실패 시 오류 메시지를 출력한다.

---

### 3.3.3 파일을 업로드한다.

1. 사용자는 업로드 요청을 보낸다.
2. 시스템은 파일 정보를 확인한다.
3. 시스템은 파일 DB에 저장한다.
4. 시스템은 업로드 완료 메시지를 반환한다.

---

### 3.3.4 파일을 다운로드한다.

1. 사용자는 다운로드 요청을 보낸다.
2. 시스템은 파일 권한을 확인한다.
3. 시스템은 파일을 사용자에게 전송한다.

---

### 3.3.5 파일을 공유한다.

1. 사용자는 공유 요청을 보낸다.
2. 시스템은 공유 권한을 저장한다.
3. 시스템은 공유 완료 메시지를 반환한다.

---

### 3.3.6 파일을 검색한다.

1. 사용자는 검색 조건을 입력한다.
2. 시스템은 파일 DB를 조회한다.
3. 시스템은 검색 결과를 반환한다.

---

### 3.3.7 파일 버전을 복원한다.

1. 사용자는 버전 목록 조회를 요청한다.
2. 시스템은 버전 목록을 반환한다.
3. 사용자는 복원할 버전을 선택한다.
4. 시스템은 해당 버전을 복원한다.

---

### 3.3.8 로그를 조회한다.

1. 관리자는 로그 조회 요청을 보낸다.
2. 시스템은 로그 DB를 조회한다.
3. 시스템은 로그 목록을 출력한다.
