## 1. 서론

### 1.1 문서 목적 및 범위

본 문서의 목적은 **Mini Drive(클라우드 파일 공유 시스템)** 프로젝트에 대한 테스트를 설계하고 그 결과를 기록하는 데 있다.

실제 구현이 완료되지 않은 단계에서도 요구사항 정의서 및 요구사항 분석서를 기반으로 테스트 케이스를 설계하여, 향후 구현 시 검증 기준으로 활용할 수 있도록 한다.

본 문서에서는 Mini Drive의 테스트 기준, 테스트 범위, 테스트 케이스 목록과 테스트 결과(예상 결과)를 명시한다.

### 1.2 프로젝트 개요

Mini Drive는 조직 내 파일을 중앙에서 관리하고 사용자 간 공유를 지원하는 **웹 기반 클라우드 파일 공유 시스템**이다.

기존에 이메일, 메신저, 개인 클라우드 등 여러 경로로 분산된 파일 관리 문제를 해결하기 위해, 파일 업로드/다운로드, 폴더 관리, 권한 기반 공유, 버전 관리, 검색 기능을 하나의 시스템에서 제공한다.

**기술 스택:** Frontend - HTML/CSS/JavaScript, Backend - Java Spring Boot, Database - MySQL, 형상관리 - Git/GitHub

### 1.3 용어 정의

| 용어 | 설명 |
|------|------|
| 사용자 | 시스템에 로그인하여 파일 업로드, 다운로드, 공유 등의 기능을 사용하는 일반 사용자 |
| 관리자 | 사용자 계정 관리 및 시스템 운영을 담당하는 사용자 |
| JWT | JSON Web Token — 사용자 인증 및 세션 관리에 사용되는 토큰 |
| 버전 관리 | 파일 변경 이력을 저장하고 이전 버전으로 복원하는 기능 |
| 공유 링크 | 외부 사용자에게 제공하는 파일 접근 URL |
| 메타데이터 | 파일 이름, 크기, 업로드 시간 등 파일에 대한 정보 |
| RBAC | Role-Based Access Control — 역할 기반 접근 제어 |
| 블랙박스 테스트 | 시스템 내부 구현을 모른다는 가정 하에 외부 인터페이스 기반으로 수행하는 테스트 |

## 2. 테스트 개요

### 2.1 테스트 범위

테스트는 **블랙박스 테스트** 방식으로 수행한다. 시스템 내부 구현을 확인하지 않고 사용자 시점에서 기능의 입출력 및 동작을 검증한다.

| 범위 | 내용 |
|------|------|
| 사용자 계정 기능 | 회원가입, 로그인 동작 정확성 및 요구사항 충족 확인 |
| 파일 관리 기능 | 업로드, 다운로드 동작 정확성 및 메타데이터 저장 확인 |
| 폴더 관리 기능 | 폴더 생성, 수정, 삭제 및 파일 이동 확인 |
| 공유 기능 | 사용자 간 공유 및 외부 링크 생성 확인 |
| 검색 기능 | 이름, 날짜, 유형, 사용자 기준 검색 결과 확인 |
| 버전 관리 기능 | 버전 이력 저장, 조회, 복원 확인 |
| 비기능 테스트 | 성능(응답속도), 보안(비인가 접근 차단), 브라우저 호환성 확인 |

### 2.2 테스트 항목 및 통과 기준

| 분류 | 테스트 항목 | 통과 기준 |
|------|------------|----------|
| 기능 | 회원가입 | 올바른 이메일/비밀번호 형식만 가입에 성공한다 |
| 기능 | 로그인 | 올바른 계정 정보만 로그인에 성공하며 JWT 토큰이 발급된다 |
| 기능 | 파일 업로드 | 유효한 파일이 클라우드 스토리지에 저장되고 메타데이터가 DB에 기록된다 |
| 기능 | 파일 다운로드 | 권한이 있는 사용자가 파일을 정상적으로 수신한다 |
| 기능 | 폴더 관리 | 폴더 생성/수정/삭제가 계층 구조에 정상 반영된다 |
| 기능 | 파일 공유 | 대상 사용자에게 권한이 부여되고 이메일 알림이 발송된다 |
| 기능 | 외부 링크 공유 | 고유 URL이 생성되고 만료 기간이 적용된다 |
| 기능 | 파일 검색 | 조건에 해당하는 파일 목록이 3초 이내에 반환된다 |
| 기능 | 버전 관리 | 이전 버전 조회 및 복원이 정상 동작한다 |
| 비기능 | 응답 성능 | 로그인·검색·다운로드 초기 응답이 3초 이내이다 |
| 비기능 | 보안 | 비인가 사용자의 파일 접근이 차단된다 |
| 비기능 | 브라우저 호환 | Chrome, Edge에서 시스템이 정상 동작한다 |

## 3. 테스트 케이스

### 3.1 테스트 케이스 선정

테스트 케이스는 요구사항 정의서의 기능적·비기능적 요구사항(FR-001 ~ FR-029, NFR-001 ~ NFR-016)과 유스케이스(U_01 ~ U_11)를 기준으로 선정하였다.

블랙박스 테스트 기법을 기반으로 사용자 시점에서의 입출력 검증에 중점을 두며, 경계값 분석 및 동등 분할 기법을 활용한다.

### 3.2 테스트 케이스 유형

- **입력 유효성 테스트:** 이메일 형식, 비밀번호 정책, 파일 형식/크기 등 입력값 검증
- **동작 테스트:** 버튼 클릭, 파일 선택 등 사용자 행위에 따른 시스템 동작 확인
- **권한/보안 테스트:** 역할에 따른 접근 제어 및 비인가 접근 차단 확인
- **성능 테스트:** 응답 속도 측정 (로그인·검색·다운로드 3초 이내)
- **호환성 테스트:** 브라우저(Chrome, Edge) 환경에서의 동작 확인

## 4. 테스트 예외사항

### 4.1 중단 기준과 재개 조건

| 중단 기준 | 재개 조건 |
|---------|---------|
| 파일 업로드 시 서버 내부 오류(500)가 발생한 경우 | 서버 오류를 수정하고 업로드 기능이 정상화된 후 재개 |
| 로그인 인증 모듈 오류로 모든 로그인 시도가 실패하는 경우 | 인증 서버 복구 후 재개 |
| DB 연결 장애로 데이터 저장/조회가 불가한 경우 | DB 연결 복구 후 재개 |
| 시스템 input type과 다른 input이 지속 입력되어 예외 처리 불가한 경우 | 입력을 중단하고 기존 데이터로 시스템을 재개 |
